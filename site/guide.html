Beginner guide

Start the project, try one normal portal task, and then work through the security labs one at a time.

Keep this local. The app contains insecure code on purpose and should not be placed on a public server.

1. Start the project

Install Docker Desktop, open a terminal in the project folder, and run:

docker compose up --build

Open the app at localhost:8000. The companion page is at localhost:8080.

2. Try the portal

Sign in as admin@email.com with Password1. Open User Search and run a search. You can also try the faculty account scienceguy@email.com / Password2 or student account student@email.com / Password5.

3. CWE-640: weak password recovery

  1. Open Lab Exercises and choose CWE-640.
  2. Enter a sample email such as student@email.com.
  3. Notice that the reset URL only contains the email. It has no random secret token.
  4. Open the URL and set a new password.

The problem is that anyone who can guess an account email can build the same link.

4. CWE-613: session expiration

  1. Sign in and open the CWE-613 lab.
  2. Click Pretend session is very old.
  3. Go back to the dashboard. The old session still works.

A real app should check an inactivity or absolute timeout before accepting an old session.

5. CWE-384: session fixation

  1. Open the CWE-384 lab and keep the prefilled session ID.
  2. Sign in with a sample account.
  3. The app keeps the chosen ID instead of generating a new one after login.

If an attacker already knows that ID, they may be able to reuse the signed-in session.

6. Stop and reset

Press Control+C in the Docker terminal. Starting the project again resets the teaching database, so the exercises are repeatable.
